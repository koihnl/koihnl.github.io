数据如何存储，如何被保障

如何存储

IndexedDB 本地数据库：全部待办、记录、永久待办、标签、草稿、回收站与操作日志均保存在您自己的浏览器本地，不经过任何服务器，离线可查、关页不丢；旧版本地数据会自动迁移，浏览器不可用时自动降级到 localStorage 兜底。

准确性

输入即校验：新增与编辑均做空内容拦截；每条记录以UUID 唯一标识，修改、完成、删除只作用于该条，避免误改误删；操作即时落库。

完整性

事务化读写：写入采用数据库事务，失败自动回滚；每条数据都补齐关键字段后再入库，导出 JSON 全量备份覆盖所有日期与设置，导入可整体恢复。

一致性

单一数据源：日历、搜索、列表全部由同一份数据渲染；标签改名、记录类型改名自动同步到所有历史条目，删除标签可自由选择是否保留事项。

及时性

即改即存：每次增删改查即时写入并刷新界面；关闭页面自动保存；操作日志完整记录每一步动作与时间，可随时回看追溯。

容量充足

IndexedDB 按浏览器配额动态分配：桌面浏览器通常可达数百 MB 至数 GB（约为磁盘剩余空间的 60%），移动端也有约 100MB+。本工作台单条数据约 0.5–1KB，可轻松存储数十万条待办与记录。当前：…，数据管理区实时显示已用与可用额度，超过 60% 变黄提醒、90% 变红预警。

数据 100% 保存在您的浏览器本地，绝不上传任何服务器。 建议定期使用「数据管理 · 导出 JSON 备份」留存副本；清理浏览器数据前请先导出。

设置

· 一个待办可打多个标签；删除标签时可按需选择「只删标签保留事项」或「同时从所有事项移除该标签」。
